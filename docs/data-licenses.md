## 1. Quran Foundation Content API
Rules from the brief:
- Credentials live only on our backend. Clients never call QF directly.
- Do not publish QF content or raw API data in repos or downloadable files.
- Do not resell or redistribute, and do not use it to train models.
- Cache at most 1 week unless we adopt their Content Sync.
- Credit "Quran Foundation" in the app credits screen, and credit the reciter for audio.
- Prelive and production tokens are not interchangeable.

How the architecture enforces this:
- The backend cache has a hard TTL of 7 days.
- `.gitignore` excludes cache and raw content directories.
- Seed files in `content/seed` contain only our own data, such as lesson structure and Shane Nuzul entries. They contain no QF text.
- Word-level frequency stats are computed at runtime from cached data and are not committed.

Open question: the "own data model" stores Arabic text and word records (`Word.arabicText`). Whether persisting QF-derived Arabic text in our SQL database counts as redistribution or exceeds the 1-week cache rule needs confirmation from QF. Until then, treat the Word table as a cache of QF data (expiring in ≤7 days) or populate it from a source cleared for permanent storage. See open questions in architecture.md.

## 6. Audio
- Word audio: `audio.qurancdn.com` via QF `word.audioUrl`. Credit QF.
- Ayah and chapter audio: credit the reciter by name, as returned by the API.
- Offline downloads are user-initiated only. The credits screen must be reachable offline, and deleting a download must remove the files.
- ❓ Confirm that QF terms permit offline copies on user devices.

## 7. Shane Nuzul
No clean free API found. We keep our own `ContextCard` table with `reviewStatus` of Draft or Reviewed. Only Reviewed rows are shown in the UI. Each row must name its source work. Seed items are marked "needs scholar review".

## 8. Findings from running the app (2026-11-20)
- The dev source api.alquran.cloud and QuranEnc both worked without a key. QuranEnc's Bengali text is passed through unmodified and shown with source "QuranEnc.com".
- **QuranEnc version number is not configured** (`QuranEnc:Version` is empty), so the UI currently omits it. The brief requires showing it. Fill it in from the QuranEnc page for `bengali_zakaria`.
- QuranEnc's text contains footnote markers such as `[১]`. They are shown as-is because the text must not be modified.
- Nothing has been run against the real Quran Foundation API: there are no credentials yet. Its response field names in `QfContentSource` follow public Quran.com v4 documentation and are unverified.
- Roots (`Word.RootId`) are not populated. QuranMorph and QUL have not been evaluated, so the "root / same-root words" part of the chip is not shown.
